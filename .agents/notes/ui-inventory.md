_Baseline from the 2026-10-15 modernization audit of `main` at `6e22d7f`. This is the source list for the transition registry in epic #99 (`tests/ui-transitions.json`). Once that registry exists, update the registry, not this file._

## Inventory

References below are relative to the repository root. An inventory item is a family of separately assertable transitions: each semicolon-delimited behavior needs its own assertion in the transition registry. “Preserve” means preserve existing supported behavior; negative tests and currently unverified browser combinations must not be labelled already passing. New improvements should have distinct acceptance tests and separately reviewed visual expectations.

### 1.2 Global appearance, controls and session lifecycle

Sources: `src/routes/theme.ts`, `control-plane.ts:456`, `src/ui/{select,select-browser,select-styles,menu-styles,management-ui}.ts`, `src/commentor/recovery-session.ts`.

- **G01 Theme initialization:** absent/invalid/unavailable storage resolves to system; initialize before paint; retain `commentor-theme` key and system/dark/light meanings across landing, auth, management and viewers.
- **G02 Theme interaction:** system → dark → light → system; button icon/label/title; 300ms icon track and 520ms radial reveal; rapid clicks preserve latest intent; snapshot rejection and unsupported View Transitions switch directly; preference saved before navigation; reduced motion switches directly.
- **G03 Theme synchronization:** OS theme changes only affect system mode; storage events synchronize other tabs without replaying animation; BFCache reconciles saved intent; parent sends theme to commentor only; publisher document CSS/colors remain unchanged.
- **G04 Shared field/button semantics:** hover/focus/press, disabled/pending, required/invalid/described fields, error/status live regions, 36/40px control variants and 44px mobile targets; no duplicate pending submissions; long labels and translated browser validation messages remain contained.
- **G05 Shared select opening/position:** native single-value select retained for form data; enhanced trigger/listbox/checkmark; one open popup; disabled option/optgroup and hidden options; popup flips/clamps to visual viewport and stays inside owning modal; scroll/outside/blur/route/dialog/sign-out close; resize/transition repositions.
- **G06 Select keyboard:** Enter/Space open and commit; Arrow/Home/End/PageUp/PageDown; Alt-arrow behavior; 700ms typeahead and repeated-letter cycling; Escape cancels; Tab commits without trapping focus; aria-activedescendant/expanded/selected and focus restoration.
- **G07 Select lifecycle:** property updates to value/selectedIndex/disabled; async option updates; form reset; required validation focuses trigger and announces error; unchanged property writes do not create observer loops; remove/reinsert controls cleanly; native multiple/size>1 and no-JS controls remain native.
- **G08 Destructive confirmation:** shared themed dialog, safe text insertion, action-specific title/message, default Cancel focus, explicit confirm, Escape/backdrop cancel, trigger focus restoration, overlapping prompt cancellation, native-confirm compatibility fallback. Test every caller, not just the shared implementation.
- **G09 Ordinary dialogs:** open/create/invite triggers; native focus containment; close button/Cancel/backdrop/Escape; prevent closing while a write is pending; preserve entered values on failure; reopen behavior; mobile footer ordering and viewport fit.
- **G10 Feedback:** button-local copy pending → Copied/check → original label; repeated copying resets feedback timer; clipboard denial has actionable manual-copy text; toasts enter, announce and expire; failures do not use raw HTML from server text; ID truncation/title/copy and shared role/status/scope vocabulary.
- **G11 Sign-out:** GET confirmation screen without revocation; same-origin native POST and enhanced submission; failed POST shows Try again and retains cookies; complete HTML offers Sign in; same-tab cleanup; cross-tab BroadcastChannel plus storage fallback; close top-layer dialogs/popovers even if secret/draft blockers exist; hide/inert protected content; focus signed-out notice; explicit Sign in link; stop queries/subscriptions/pending writes and reject late UI results; do not force other tabs to navigate.
- **G12 Session restoration:** focus/BFCache checks live user; revoked or changed account hides old data; network failures do not impersonate a successful logout; comment drafts remain only in their original user namespace, and are cleared on a different user; auth cookie cleanup failure UI stays usable.

### 1.9 Required dimensions of the checklist

Every applicable transition above gets a stable ID, expected visible result, expected request/authorization result, fixture, and test location. Use owner/admin/member/outsider, anonymous/expired/revoked/changed session, zero/one/many data, long hostile names, and success/validation/permission/offline/429/503/ambiguous-write outcomes. Pair failed operations with valid controls.

Exercise all transition assertions in Chromium, Firefox and WebKit desktop; add mobile/touch projects at 320, 375 and 430 CSS pixels, and a desktop width. All components need light/dark, keyboard and reduced-motion coverage. The entire combinatorial cross-product need not run on every commit: require each transition in all engines, plus representative dimension pairs per component and all security/race combinations. Use physical Safari/mobile acceptance for browser features where emulation differs. No-JS/unsupported clipboard/storage/popover/ViewTransition/activation/observer cases must reflect actual current fallbacks, not imagined functionality.

Authoritative code takes precedence over historical descriptions. Keep legacy surfaces until an explicit, separately authorized retirement; do not use the modernization as an excuse to delete URLs, data, comments or API contracts.
