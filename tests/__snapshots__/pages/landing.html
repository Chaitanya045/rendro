Workflow

From repository to readable docs.

Rendro reads the repository your team already writes, reviews and merges in, so the docs are the ones on the branch.

Where Rendro looks for docs

  • mkdocs.ymlits docs_dir
  • docusaurus.config.*the docs folder beside it
  • .vitepress/config.*its source directory
  • book.tomlthe mdBook source
  • docs/a Markdown folder
  • index.htmlprebuilt HTML pages
  • README.mdthe fallback

GitBook, Mintlify and Docsify layouts are detected too. The strongest signal wins.

Product

A docs workspace for every repository.

Rendro owns the workspace around the page: navigation, search and comments. Each page is rendered from the repository and shown in its own sandboxed frame.

01 / NAVIGATE

File-tree navigation and search

Folders load on demand, search finds any section of the docs, and links between pages keep the tree on the page you are reading.

02 / RENDER

Markdown and HTML from the repository

GitHub-flavoured Markdown with tables, task lists, footnotes, alerts and highlighted code, and HTML pages, sanitized and set in one GitHub-style reading theme.

03 / REVIEW

Comments on any page

Select text to open a thread. Replies arrive live, authors can edit their own comments, and a thread stays on its text when a new commit changes the page around it.

04 / DELIVER

Served from the edge

Pages are rendered once, when a commit is ingested, and served from Cloudflare's edge. Navigation stays inside the shell, and a likely next page is prefetched before you open it.

Security

Private stays private. Access follows GitHub.

Rendro keeps no permission model of its own. The people who can read a repository on GitHub can read its docs and comments, and nobody else.

Get started
Access
Every view is checked against the repository's GitHub permissions, which Rendro mirrors. When GitHub removes someone's access, their access to the docs and comments ends too.
Public repositories
Anyone can read the docs of a public repository. Commenting needs a signed-in account.
Private content
Sealed per repository with AES-256-GCM in storage and in the edge cache, and opened only after the reader is authorized.
Rendering
Repository HTML is sanitized against an allowlist, with no scripts, styles or event handlers, and shown in a sandboxed frame.
